# 圖表編制準則（Figure Guidelines）

> 適用範圍：本站所有專案頁的內嵌圖與表（`<Figure />`）。版本：1.0（2026-11）。
> 元件用法與屬性清單見 README 的「Add a figure」與 `src/components/Figure.astro` 開頭的說明；這份文件只規定**圖表該長什麼樣子、為什麼**。

## 1. 這是什麼、為什麼需要

圖表在 build 時由 CSV 畫成 SVG 與 HTML，直接排進內文，網頁不載入任何 JavaScript。因為所有圖共用同一個元件，版面一致性由程式保證；這份準則記錄的是程式背後的判斷，以及寫 CSV、標題、說明文字時要遵守的規則。

準則的核心只有一句：**文字不壓線，線不穿過文字，留白先於放大。**

## 2. 版面結構

每張圖或表由上到下固定五層，順序不可調換：

| 順序 | 元素 | 規則 |
| :-: | --- | --- |
| 1 | 標題 | 自動編號，圖與表分開計數（Figure 1、Table 1）。寫「這張圖量的是什麼」，不寫結論 |
| 2 | 檢視切換 | 只有設定 `toggle` 時出現，最多 6 個選項 |
| 3 | 圖例 | 在圖的上方，順序與圖中由淺到深或由左到右一致。地圖在寬螢幕時圖例移到右側 |
| 4 | 圖或表本體 | 見第 3、4 節 |
| 5 | 說明與來源 | 說明寫「怎麼讀」，一到兩句。來源是最後一行，開頭自動加上資料性質 |

圖與上下段落之間留 2.75rem，圖內各層之間留約 1rem。覺得擠的時候加間距，不要縮小字。

## 3. 圖的規則

### 3.1 列與群組（學術表格的 stub 與 spanner）

| 規則 | 做法 | 理由 |
| --- | --- | --- |
| 列名靠左對齊，像表格的首欄 | 元件自動處理 | 讀者由左到右讀，名稱與資料在同一條水平線上 |
| 群組名稱獨占一列，粗體 | 設定 `group` | 群組名稱是標題，不是資料 |
| 群組名稱那一列不畫任何格線 | 垂直格線與參考線在每個群組的資料列內分段繪製 | 文字壓在線上或用底色蓋掉格線，都會讓圖看起來髒 |
| 第二個群組起，上方多留一段空白 | `GROUP_GAP`（16px） | 用留白分組，不用框線 |
| 列名放不下時改放在該列上方 | 點圖：列名超過圖寬的四成時，自動改成「名稱一行、資料一行」，格線只畫在資料那一行 | 手機寬度只有 350px，名稱擠在左邊會把圖壓扁 |
| 色塊矩陣的列名約 20 個字元以內 | 超過圖寬一半時 build 會失敗 | 矩陣需要首欄對齊，無法把名稱移到上方 |

列高、群組列高、群組間距與名稱行高定義在 `src/lib/figures/theme.ts`（`ROW`、`HEAD`、`GROUP_GAP`、`NAME_LINE`），要調整只改這四個數字。

### 3.2 座標軸與格線

| 規則 | 做法 |
| --- | --- |
| 格線用最淡的線色（`--rule`），參考線用較深的墨色 | 自動 |
| 刻度數字用等寬字，軸標題用內文字體 | 自動 |
| 刻度數字彼此不可相碰 | 放不下時先改成只標 10 的次方，再不行就每隔一個標一次；格線仍然每個都畫 |
| 軸標題寫明單位；對數軸寫「(log scale)」 | `xLabel`，約 40 個字元以內 |
| 參考線要有名稱 | `reference` 搭配 `referenceLabel`。名稱放在第一個群組那一列、線的正上方；會碰到群組名稱時自動改放到最上方 |

### 3.3 點與數值標籤

| 情況 | 做法 |
| --- | --- |
| 每一列每個系列只有一個點 | 數值直接印在點的旁邊；同一列有兩個系列時，左邊的點數值印在左側、右邊的印在右側，兩個數字不會疊在一起 |
| 每一列有多個點 | 不印數值，滑鼠停留或手指點按時顯示 |
| 兩個點的數值完全相同 | 合併成一個標籤，列出全部名稱（例如「EUR/USD and USD/JPY 1.34」），並在說明文字註明 |
| 點互相重疊或幾乎相接（同一列中心距離小於 15px） | 共用一個橫跨這些點的感應範圍；標籤第一行是列名，接著由左到右每個數值一行。每個點仍有紙色外框把它們分開 |
| 點彼此分開 | 滑鼠的感應範圍等於點的大小（手指點按時加大一倍），所以標籤一定屬於游標下那個點 |

### 3.4 色塊矩陣

- 相鄰色塊之間留 2px 的紙色間隙，不畫框線。
- 格內文字在深色格用淺色字、淺色格用深色字，由元件依顏色決定。
- 欄名放不下時自動轉成直書，不縮小字。

### 3.5 地圖

- 一個 census tract 就是一個填色的區塊（面量圖），邊界來自 `geometry` 指定的形狀檔，CSV 用 `place` 欄（GEOID）對應。沒有底圖；城市的形狀由 tract 本身呈現。
- 區塊之間用一條很細的紙色線分開（約 0.5px），不畫深色邊框。
- 三種「沒有顏色」要分得開：數值留空（例如未達顯著）用中性灰，圖例文字由 `blank` 設定；不在分析內的 tract（公園、機場等人口太少的區域）用更淡的灰，圖例文字由 `outside` 設定，預設「Not in the analysis」。
- 地圖不提供數值標籤，兩千多個區塊的標籤會讓頁面過重。要比較不同變數時用 `toggle`。
- 有 `toggle` 時，地圖只畫一次，切換檢視時改的是填色，所以檢視再多，頁面大小也只多一點。
- 形狀檔的繪圖比圖高寬 1.3 倍以上（例如一排小地圖）時，地圖佔滿欄寬、圖例放在上方；其他地圖在寬螢幕時圖例在右側。
- 示意圖也走同一個元件，但只能用公開資料（例如邊界本身的面積），並在說明裡寫清楚它不是分析結果。
- 形狀檔只能有幾何與 GEOID。任何屬性資料（人口、就業等）都不放進 repo。

## 4. 表的規則

`type="table"` 把 CSV 原樣印成表格，遵守期刊表格的慣例：

| 規則 | 做法 |
| --- | --- |
| 只有三條橫線：表頂、欄名下方、表底 | 自動；不畫直線，列與列之間不畫線 |
| 欄名就是 CSV 的欄名 | 所以 CSV 欄名要寫成可以直接給人看的文字，並帶單位（例如 `Gross rent, $`） |
| 數字欄靠右對齊、等寬字 | 一欄的每一格都是數字時自動判定 |
| 小數位數一致 | 在產生 CSV 時就格式化好；元件不會改動任何一格 |
| 首欄是列名，不換行 | 自動 |
| 欄位控制在六欄左右，儲存格文字要短 | 欄名可以換行；平板以上的寬度不應需要左右捲動 |
| 手機上表格過寬 | 表格本身可以左右捲動，頁面不會 |

## 5. 顏色

所有顏色都是 `src/styles/global.css` 的 CSS 變數，圖表程式裡沒有任何色碼。

| 資料的性質 | 用色 | 變數 | 怎麼觸發 |
| --- | --- | --- | --- |
| 兩個系列互相比較 | 海軍藍與中性灰 | `--data-1`、`--data-2` | 點圖的 `color` |
| 數值大小（沒有負值） | 單一色相由淺到深，五級等距 | `--seq-1` … `--seq-5` | `color` 欄全是數字 |
| 數值有正有負 | 負值鏽色、正值海軍藍，零的兩側各三級，級距相同 | `--neg-*`、`--pos-*` | `color` 欄出現負數 |
| 有順序的類別 | 單一色相由淺到深 | `--seq-*` | 文字欄加上 `order="A, B, C"` |
| 沒有順序的類別（分群結果） | 五個可互相區分的顏色，依名稱排序指定 | `--cat-1` … `--cat-5` | 文字欄且不給 `order`，最多五類 |
| 沒有數值 | 中性灰 | `--data-none` | CSV 該格留空 |
| 地圖上不在分析內的區塊 | 更淡的灰 | `--data-out` | 形狀檔有、CSV 沒有的地點 |

- 「單一強調色」是網站介面的規則；圖表在需要區分正負或類別時使用第二個色相。
- 有 `toggle` 時，類別的顏色在每個檢視都相同。數值預設每個檢視各自分級（適合不同變數）；各檢視是同一個變數時加上 `sharedScale`，讓同一個顏色在每個檢視代表同一個數值。
- 顏色不是唯一的資訊來源：類別同時有圖例文字，色塊矩陣可以印出文字，數值可以用標籤讀到。
- 新增或修改顏色時，用色覺辨識檢查工具確認相鄰顏色在色盲模擬下仍分得開，再改變數值。

## 6. 文字

| 元素 | 規則 | 例子 |
| --- | --- | --- |
| 標題 | 名詞片語，說明量的是什麼與單位；句首大寫，其餘小寫 | How often losses exceeded the 1% VaR forecast |
| 說明 | 先寫一個點或一格代表什麼，再寫怎麼判讀方向 | Each dot is one currency pair. Right of the line the model understated risk. |
| 來源 | 資料出處、期間、樣本數；若由腳本產生，寫出腳本路徑 | Thesis Table 5-2. Out-of-sample period January 2020–December 2025. |
| 內文引用 | 圖上讀得到的數字才寫進內文，數字必須與 CSV 一致 | |

全站規則同樣適用：只用英文、不用全大寫、日期範圍用 en dash、少用「—」「&」「·」。

## 7. 資料

| 規則 | 說明 |
| --- | --- |
| CSV 說什麼，圖就印什麼 | 元件不四捨五入、不換單位、不改排序。列的順序就是 CSV 的順序 |
| 一張圖一個 CSV | 放在 `src/data/figures/<專案檔名>/`，並在該資料夾的 `README.md` 記一行來源 |
| 地圖的形狀共用 | 放在 `src/data/figures/geometry/`，由 `scripts/build_figures.py` 的 `geometry` 階段產生；地圖 CSV 只放 GEOID，不放座標 |
| 每頁宣告資料性質 | frontmatter 的 `basis`：`published`（已發表的結果）、`public-data`（公開資料）、`simulated`（模擬資料） |
| 受 NDA 保護的資料不進 repo | 這類專案改用公開資料重跑同一套方法，並在頁面上明講 |
| 可重現 | 由腳本產生的 CSV，腳本放在 `scripts/figures/`，設定集中在 `config.py`，亂數種子固定 |

## 8. 三種寬度與瀏覽器

每張圖在 build 時各畫三次（712、520、350px），由 CSS 依欄寬選一張顯示，所以圖內文字在手機上不會縮小。地圖沒有文字，只畫一次，所有檢視共用。

說明與來源在寬螢幕左右對齊；視窗寬度 560px 以下改為靠左對齊，與內文規則相同（欄寬太窄時左右對齊會出現大空隙）。

改動元件或樣式後，至少檢查：

```text
[ ] npm run build 沒有警告與錯誤
[ ] 1280、820、390 三種視窗寬度下頁面沒有水平捲軸
[ ] 文字沒有壓到線或其他文字，刻度數字沒有相碰
[ ] 滑鼠停留與手機點按都能顯示數值，標籤沒有超出畫面
[ ] 檢視切換一次只顯示一個檢視，鍵盤左右鍵可以切換
[ ] 沒有圖表的頁面，輸出與修改前相同
[ ] 頁面沒有 <script>（JSON-LD 除外）
```
